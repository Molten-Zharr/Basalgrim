# Basalgrim

Basalgrim is a native Linux GUI/TUI file manager for Molten-Zharr.

- Rust 2024; Ratatui is the single renderer for GUI and TUI. GUI uses eframe/egui_ratatui/soft_ratatui; TUI uses Crossterm. Keep GUI dependencies behind `guitui` and terminal dependencies behind `tui`.
- Share behavior through `App`, `Action`, and `Input`. Register hit regions in the same renderer that draws their controls. Don't duplicate filesystem logic in either frontend.
- Every file command must be reachable with the mouse, including compact layouts. Keep the shared Actions menu, secondary clicks, independent mark controls and modal dismissal without click-through. Native GUI clipboard shortcuts must preserve raw keys and exact modifiers before egui's clipboard interception, including an empty OS clipboard; verify the real GUI with scripts/smoke_gui.py when changing input.
- Right-click menus are contextual: one entry, a marked group, or the current directory background. Show only applicable available commands; keep global commands in Actions/Shift+F10. Each command row owns its hover hit region even when disabled; menu background and outside-dismiss regions must never receive hover tint.
- Hover is separate from selection and keyboard focus. Resolve the topmost current hit region after modal rendering; tint only its background and preserve selected backgrounds. Pointer movement must not navigate, change selection, mark files, or request previews. Clear hover when the pointer leaves or the terminal loses focus.
- Wheel input scrolls the hovered file pane's viewport without changing selection, marks, active pane or preview. Keep manual scrolling independent of renderer cursor-following; keyboard navigation reveals focus again. Preserve a manual viewport across refreshes and bound offsets after resize/filtering. Verify GUI and PTY wheel events, not only shared selection actions.
- Rubber-band selection uses explicit press/drag/release inputs, separate from hover, and renderer-owned file viewports/hit geometry. Keep it within the originating pane; Ctrl adds to the original set, Esc/focus loss restores it. Cancel stale gestures on directory requests, tab changes and layout changes. An explicit empty selection must not fall back to the keyboard-focused file. Draw the GUI outline after SVG composition and verify real GUI and PTY drags.
- File drags start on entries; marquee starts on renderer-owned background gaps. Preserve marked groups until a click or drag is resolved and defer double-click opening until release without motion. Drop targets capture tab/directory/request identity and geometry; accept ordinary folders, file-pane backgrounds and visible tabs. Move by default, Ctrl at release copies; keep the clipboard and use the common guarded operation worker. Esc/focus loss, stale source or layout changes cancel and restore selection. Keep autoscroll separate from selection and draw destination outlines after SVG composition. Defer background scans during pending/active drags. Plain PTY smoke tests must remove DISPLAY, WAYLAND_DISPLAY and WAYLAND_SOCKET; native clipboard tests use explicit private displays.
- Visible breadcrumb folders also accept drops through their renderer-owned tab/request snapshot, without navigation. Keep the main toolbar to navigation, creation, search and view; clipboard commands stay in shared menus/shortcuts. Function commands belong in the footer, including compact mouse targets. Toggle the second pane from its header and preserve its tabs when hidden. Render a pane-scoped new-tab + beside tabs at every supported size, reserve its space on overflow, keep the active tab visible and ignore stale tab controls.
- Cross-application drags use native XDND/Wayland GUI workers and positively negotiated local Kitty OSC 72. Bind each drop to renderer-owned tab/request/geometry before bounded URI reads; keep mouse Stop at minimum size and reject stale/cancelled batches. Never delete sender paths on protocol completion or replace the file clipboard. Keep duplicate Wayland clipboard drag offers alive until appropriate leave/drop cleanup. Preserve validated XDND proxy forwarding in vendor/winit and bounded OSC framing with standalone Escape/Alt+] in vendor/crossterm. Verify independent GTK4 peers in both native backends and fragmented protocol input in an isolated PTY; Wayland native cancellation/action changes also depend on compositor support.
- Icon geometry and classification are shared by GUI/TUI. Use embedded SVGs colored by the current Palette, and honor the persisted Images/Symbols preference. Probe terminal graphics before the input loop with a bounded synchronous read; never leave a stdin-reading probe thread or change tmux settings. Unsupported terminals use symbols. Keep image work off the TUI loop, validate asynchronous cache generations/request IDs, and prevent images from covering modals or accumulating in the cached GUI raster.
- Rename edits the renderer-owned filename rectangle in grid/list with compact mouse submit/cancel controls. Keep the editor and label text at the same origin. A pending rename displays the requested name only in captured directory snapshots; retain original action paths until the worker reports the actual published destination, including Keep Both. Apply that name before clearing the pending label, preserve focus/marks through sorting, and restore the original presentation on failure/cancellation. Check the renamed entry itself during worker and scan delays, not just its neighbours. All text fields share grapheme-aware cursor/anchor state, rendering widths, mouse/Shift selection and the four-command text menu; never dispatch file clipboard actions from an editor. Preserve busy-dialog input and reject stale rename owners. Native text paste uses the clipboard worker with independent cancellation and an editor revision; reject late responses after cursor/text/editor changes, retain the file clipboard marker, and fall back to the terminal's paste without OSC 52 reads. Verify native X11/Wayland and minimum-size grid/list PTY input; keep menu backgrounds untinted.
- Use `assets/brand/molten-zharr.json` for palette roles and the default brand colors. Appearance has four Almavorn palettes plus per-theme color overrides; build a Palette from the current Settings, without global mutable theme state. Fira Code and DejaVu Sans Mono licenses are bundled; terminal fonts remain terminal-controlled.
- Settings share one Ratatui screen. Persist all command bindings, match normalized modifiers exactly, and capture a new shortcut before dispatching actions. Keep navigation keys reserved, reject conflicts, and derive command/help labels from the active bindings. Keep the legacy JSON font_size key readable through flattened Appearance.
- File clipboard exchange shares Copy/Cut/Paste and the operation engine. Export GNOME, URI-list and KDE cut formats simultaneously, preserve raw Unix paths and reject nonlocal/malformed batches. Use the actual GUI display connection/backend; local TUI requires X11 or Wayland data-control, otherwise retain the internal file clipboard. Never send file authority through OSC 52. Keep protocol I/O and bounded transfers in a worker, cancel stale reads, capture the paste destination, and guard cut pruning by clipboard generation. Do not overwrite a later external selection or retry consumed cut paths against new occupants. Native text copies retain this instance's file selection through a marker. App::new never attaches desktop services; native tests require a private display and isolated HOME/XDG.
- Read directories, previews, and operations in workers. Validate request IDs before accepting asynchronous results.
- Bulk rename opens a plain common-name field with optional numbering and preserved per-file extensions; templates require an explicit advanced mode. Show readable Before/After names and examples at 34x14. Number toggles retain entered text; mode switches preserve both inputs and invalidate pending text paste. Verify ordinary Unicode typing in native GUI, including virtual keyboards whose text scancodes resemble Escape or function keys.
- Advanced rename templates preserve extensions by default: `Photo_{n:03}` must keep each original suffix without requiring `{ext}`. Use a consistent explicit parameter for changes: `{ext:jpg}` sets `.jpg`, `{ext:}` removes the suffix; both go at the end. Keep existing full-name templates, literal suffixes, `{full}` and `{ext}` working, without duplicating suffixes or losing dots within expanded stems. Plain mode and first mode switches must preserve their results, including dotted literal common names. Template errors name the bad fragment and its position, with concrete corrections. Preserve diagnostic line breaks and allow scrolling at 34x14; a static example must never look like the current input's actual result. Renaming does not convert file contents. Validate preview, actual filenames and undo in native GUI/PTY; passing parser tests alone do not establish usability. Rebuild the release binary used by the user when handing off a UI change, and distinguish it from an already running older process.
- Image previews share renderer-owned slots and terminal graphics detection with icons; the Icons preference must not disable content previews. Bound source/decoded sizes, keep one scaled frame per backend, cancel obsolete reads and reject stale encodings after selection/resize/hiding. Preserve aspect, EXIF orientation and theme transparency; suppress overlapping modal images and compose GUI pixels onto a clean raster. SVG previews never load referenced resources. Verify native GUI pixels and all terminal protocols with symbol icons.
- Session startup is shared by GUI/TUI. Keep App::new deterministic for tests/previews; only startup attaches storage. Restore both panes and active tabs only without an explicit CLI directory; --no-session reads/writes no session. Validate bounded/versioned data and preserve malformed files without autosaving over them. Store raw Unix paths losslessly, keep unavailable directories as error tabs, and exclude selection, filters, clipboard and operations. Write atomically through a coalescing worker with current-generation results, cancel pending writes when disabled, and flush the final snapshot on normal close. Isolate XDG_STATE_HOME in smoke tests.
- Watch all open tab directories outside the UI thread. Coalesce event bursts with a bounded delay, cancel obsolete scans between entries, rearm replaced/missing directories, and drop watches on shutdown. Background refresh preserves path-based focus, marks, filter, sort and viewport; keep the old frame while reading and defer applying results during dialogs, marquee gestures and operations. Operation completion must use the same snapshot-preserving refresh: never briefly replace loaded file panes or unchanged previews with a loading screen. Initial scans and navigation still use their own loading state. Verify external changes in native GUI and PTY without refresh input, and intermediate rename frames in grid/list.
- Never overwrite existing destinations implicitly. Keep no-replace publication, staged copies, non-following symlink copies, rejection of recursive destinations, and accurate partial-operation reports.
- Normal GUI/TUI startup attaches the shared SQLite journal; App::new and the plain filesystem API remain deterministic for tests/previews. Use the operation worker for all database I/O. Commit item/step intents before mutating user data and recheck cancellation after a potentially blocking commit. A journal failure before mutation blocks it; a recording failure afterward must preserve exact completed/cut counts and never remove published results. Recovery renames ignore cancellation and recording failures. Record raw paths, no-follow identities, actual Keep Both destinations, staging/claim paths and blocked inverse plans when evidence or old data is missing. Recover dead owners through independent file locks, never infer completion or replay filesystem actions. Drain the operation/journal worker at shutdown; external application waits use a separate worker.
- Undo/redo acts only on durable, guarded plans. Stream bounded no-follow tree snapshots and SHA-256, reject changed identities/content, occupied destinations, nested mounts and legacy/incomplete evidence. Retain created/copied data and replaced targets for redo; never auto-delete them. Keep child redo storage outside tracked parent trees. Rebind earlier inode evidence only through a verified inverse of our own move, atomically with its result. Persist busy/item/step intents before changes, block uncertain reversals after crashes, and roll back unfinished multi-step items without replacement even on cancellation or journal errors. Restore trash only through an exact data/.trashinfo identity; redo uses gio again. Keep shortcuts and mouse controls in shared Actions/F6 at minimum size and verify GUI, PTY, restart and SIGKILL.
- Undo storage disposal is explicit and confirmed, never automatic. Measure and clean through the serial journal worker; retain the audit log. Capture bounded record revisions, revalidate retained snapshots and no-follow owned containers, reject shared references and live writers, invalidate inverses durably before deletion, and preserve exact completed counts on recording failure. Cancellation finishes the current record; interrupted disposal is protected and never resumed on startup. Keep compact mouse controls and verify isolated GUI/PTY, SQL failures, restart and SIGKILL.
- Conflict decisions share one GUI/TUI modal with mouse controls at minimum size. Wait only in the worker, check cancellation and operation/request IDs, and scope batch choices to one operation. Keep Both is the default; skip is distinct from completion. Revalidate an approved target before replacing it, retain the old object until publication, and restore without replacement on failure. Never auto-delete a backup of user data; report recovery paths and count a published item before backup cleanup errors.
- Other-pane transfers capture the selected sources and the opposite active tab's directory at dispatch; require an enabled, resolved opposite pane. Duplicate uses the same worker copy engine with automatic Keep Both naming. Keep the existing clipboard and shortcut assignments; only completed moves prune matching cut paths. Expose these commands through contextual and compact shared menus.
- Cross-filesystem moves fall back only on EXDEV. Verify bounded copies and source identity/content before publication and deletion; fsync the destination before removing originals. Reject nested mounts. Claim source data privately before cleanup, never put claimed user data under an auto-deleting TempDir, and restore without replacement on failure. Preserve published copies and expose remaining-source recovery paths. Count only fully removed sources as completed moves; retain unfinished cut paths. Once source deletion starts, finish the item before honoring cancellation.
- Operation cancellation checks occur during preparation, between copy writes and before no-replace publication. Cleanup cannot be cancelled; count an atomic step once it succeeds even if cancellation races it. Coalesce worker progress, validate operation IDs, and remove only actually completed cut sources from the clipboard. Keep existing shortcut assignments when migrating new commands.
- Keep README minimal: purpose, short description, a stable general overview screenshot in the classic Molten-Zharr theme and a documentation link. That screenshot is independent of the user's selected theme. Update it for material changes to the main layout/navigation, not for each roadmap feature. Generate its ordinary folder/file scene with `python3 scripts/cargo_local.py run --example overview`; feature examples must never overwrite that output. Check the composition of the exact image linked by both READMEs, not only its theme or hash. Feature-specific illustrations and detailed instructions belong in docs/USAGE.md.
- Trash uses `gio trash` without permanent-delete fallback. Tests must isolate HOME and XDG data in the same filesystem because GLib compares source and HOME devices when choosing trash; never empty the user's trash.
- Trash is a location inside the ordinary file pane: retain toolbar, sidebar, tabs, grid/list, icons, preview and independent opposite-pane controls. Use contextual compact trash menus and the label “Восстановить”. The current breadcrumb edits the path inline; ancestors navigate, blank address-bar space is not a hidden edit button. GUI texture invalidation must include the rendered cursor, even on unchanged text; mouse caret positioning uses renderer-owned geometry and the same grapheme widths as the text.
- The shared trash browser reads bounded freedesktop catalogs off the UI thread, validates generations and preserves raw paths, focus, marks and viewport. Restore only exact data/metadata pairs from owned, non-symlink trash directories; original names come from metadata. Capture sources and destination before confirmation, use the common conflict/move worker, retain claimed metadata for guarded undo/redo, and recover failed claims without replacement despite cancellation or journal errors. Never auto-delete restored data or replay an interrupted restore. Keep mouse controls at 34x14 and test real gio, GUI/PTY and SIGKILL with isolated HOME/XDG directories. Permanent-deletion native tests must also use --trash-home-only so host volume trash is excluded. Deletion captures exact no-follow trash objects, including orphan metadata; empty ignores filters, refreshes before confirmation, preserves later arrivals and undo storage, journals claims before removal, rejects nested mounts and defers cancellation until the current item is finished. Never resume destructive claims automatically after a crash.
